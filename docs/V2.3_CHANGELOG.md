# RescueNepal.info v2.3 Change Log

Base: Complete Fresh Source v2.2.

## Added
- Public universal `Find My Family Member` search.
- Public `Rescued Person` registration for people rescued without a prior app request.
- Known/unknown rescued-person identity, condition, rescue/current location, institution and contact data.
- Family Match Request workflow with recent-photo upload and optional SMS OTP webhook.
- Admin Family Match Request review queue.
- Restricted DVI / recovered-deceased registration.
- Body ID, forensic reference fields and non-graphic public DVI representation.
- Deterministic AM/PM-style candidate reconciliation against missing-person records.
- Separate formal deceased identification approval with requester/reviewer separation of duties.
- Controlled public release of an officially confirmed identity.
- Append-only DVI chain-of-custody event log.
- Rescued-person family reunification record.
- Confirmed-deceased family handover with approval and automatic custody release event.
- Dedicated admin-only restricted media endpoint for DVI and family-submitted photos.
- Access-denied `uploads/evidence` and `uploads/family` directories.
- New dashboard cards/filters/actions for Rescued Persons, DVI/Deceased and Family Requests.
- XLSX sheets for rescued details, DVI data, custody, handovers and family requests according to role.
- v2.2→v2.3 migration SQL.

## Safety/privacy hardening
- Deceased recovery photos cannot render publicly and are not directly web-accessible.
- Family-submitted matching photos are restricted from direct web access.
- Normal case updates/API cannot set formal DVI confirmation or handover states.
- Deceased similarity score cannot be used as formal confirmation.
- Deceased handover requires confirmed identity and Approver/Superadmin authorization.
- Public DVI results exclude DNA, fingerprints, post-mortem details, forensic notes and personal officer contacts.
- OTP verifies possession of a phone only; relationship/identity still requires staff verification.

## Compatibility
- PHP 8.1+
- MySQL/MariaDB
- Same fresh-install `/setup` model as v2.2
- Existing v2.2 production DBs use `deployment/MIGRATE_v2.2_to_v2.3.sql` after backup.
